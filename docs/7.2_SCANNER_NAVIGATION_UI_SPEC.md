# Media Archiver 7.2 — Scanner navigation and UI specification

Status: accepted working specification based on Firefox extension and Discord userscript field feedback from 2026-08-05.

## Terminology

The runtime and UI must describe time, not screen geometry:

- **Older messages**: messages closer to the first message in the channel.
- **Newer messages**: messages closer to the latest message in the channel.
- **Oldest boundary**: the beginning of the available channel history.
- **Newest boundary**: the latest available message in the channel.
- **Current position**: the message window currently rendered when the operation starts.

User-visible copy must not use ambiguous `up`, `down`, `top`, `bottom`, `start`, or `end` for scan direction. Internal geometry may still use scroll coordinates, but direction APIs must use `older` and `newer`.

## Confirmed defects

### Firefox extension does not move the Discord timeline

Observed behavior: the interface works, but starting a scan produces no visible timeline movement.

Required fix:

1. Discover multiple Discord scroll-container candidates.
2. Probe whether a candidate is writable by applying a tiny reversible movement.
3. Select only a candidate whose scroll position or visible message window actually changes.
4. Re-resolve the scroller if an attempted navigation step produces no position, message-ID, timestamp-range, or height change.
5. Emit a stable diagnostic code instead of silently looping when no candidate can move.
6. Exercise the same movement watchdog in userscript, Firefox extension, and Chromium extension builds.

The current single-candidate `scrollTop` assumption is insufficient.

### Direction and boundary semantics are confusing

The current UI exposes combinations such as `End → start`, `Current position → end`, and `Full timeline: current → start → end`. These terms mix viewport geometry with message chronology and have caused scans to run toward older messages when newer messages were requested.

Required replacement in normal mode:

- **From current position toward older messages**
- **From current position toward newer messages**

Unreliable automatic jumps to the oldest or newest channel boundary are removed from the primary UI until the new seek engine has movement verification. They may return only as a verified automatic scope, not as manual `jump to start/end` wording.

## Date interval is a scan mode, not only a filter

Enabling a date interval hides the manual direction selector. The scanner chooses navigation and pacing automatically.

### State machine

1. **Locate interval**
   - Read only lightweight rendered message timestamps and IDs.
   - Do not collect media while travelling to the interval.
   - Do not populate the Library with media outside the requested interval.
   - Choose `older` when the visible window is newer than the interval.
   - Choose `newer` when the visible window is older than the interval.
   - Begin interval scanning immediately when the visible window overlaps the requested interval.

2. **Scan interval**
   - Switch from fast seek pacing to the established overlap-safe scan pacing before entering the requested boundary.
   - Collect and deduplicate media only while the visible message window intersects the inclusive local-date interval.
   - Preserve the existing safe scan behavior that has not shown skipped-media regressions.

3. **Complete interval**
   - Stop after the visible window has crossed the opposite interval boundary and the final overlap window has been scanned.
   - Keep date eligibility as a defensive final check, but not as the primary mechanism for excluding months or years of unrelated media.

### Starting inside the interval

When the current rendered window is already inside the interval, the controller chooses the nearer date boundary first, scans to it, reverses with an overlap anchor, and then scans through the complete interval to the opposite boundary. Canonical deduplication prevents duplicate archive records.

### Adaptive seek pacing

The seek phase may use larger verified edge jumps than the safe collection phase. It must:

- verify actual viewport/message-window progress after every jump;
- retry with a smaller step when Discord does not move;
- reduce step size near the target interval;
- never claim success based only on assigning `scrollTop`;
- transition to the established safe scanner before media collection begins.

## Boundary detection

Boundary detection must be locale independent wherever possible.

### Newest boundary

Primary signals:

- writable scroller is at its newest loaded edge;
- visible message IDs/timestamp range stop advancing toward newer messages;
- scroll height and rendered message window remain stable during the confirmation period;
- machine-readable `time[datetime]` values or Discord snowflake timestamps identify the visible dates.

Visible labels such as a time-only value or localized `Yesterday` text may be secondary hints only. They must not be required because Discord localizes presentation text and may change wording.

### Oldest boundary

Primary signals:

- writable scroller is at its oldest loaded edge;
- visible message IDs/timestamp range stop advancing toward older messages;
- scroll height and rendered message window remain stable during the confirmation period.

The localized channel-beginning banner, such as the German `Das ist der Anfang ...` presentation, may be an optional secondary signal only. The scanner must not maintain a fragile list of translations as its primary boundary rule.

## Position after completion

The current `Return to starting position` and `Jump to timeline end` options are not reliable enough to be presented as guaranteed actions.

For 7.2:

- **Stay where the scan finished** is the safe default.
- **Return to original message window** is shown only when a message-anchor restoration capability is verified for the active adapter/runtime.
- **Move to latest messages** is shown only when the movement watchdog can verify arrival.
- A failed restoration must be visible as a warning and must never be reported as success based on an approximate scroll ratio alone.

## UI redesign

The compact panel must not contain one vertically scrolling mega-settings page.

### Persistent area

Always visible:

- product/site label;
- current phase;
- progress;
- Found, Selected, Saved, Errors;
- Start/Stop primary action.

### Tabs

1. **Scan**
   - scope: Current position or Date interval;
   - manual chronology direction only when scope is Current position;
   - From/To dates when scope is Date interval;
   - concise human-readable plan preview.

2. **Media**
   - simple inclusion controls for Images, GIFs, and Videos;
   - provider-specific details in a closed disclosure menu;
   - collected-media summary and a button to open the full Library.

3. **Archive**
   - Review before archive or Quick archive;
   - ZIP behavior;
   - verified position-after-completion choices;
   - VirusTotal summarized as Off / Hash lookup / Upload unknown, with details in a closed disclosure.

4. **Activity**
   - concise operational log;
   - developer diagnostics behind a separate closed disclosure or dedicated dialog.

Advanced naming, provider details, diagnostics, and VirusTotal policy controls must not be expanded by default.

The panel body itself remains fixed. Large media browsing stays in the near-fullscreen Library rather than forcing the compact panel to scroll.

## Media inclusion controls

Replace the current crowded `Photos & native GIFs`, `Videos`, and `Rendered GIF previews` cards with clear independent categories:

- **Images**
- **GIFs and animated previews**
- **Videos**

Adapter/provider-specific explanations belong in contextual help or a disclosure, not in the primary control labels.

## Test requirements

### Automated

- Firefox content-script scroller selection with multiple decoy containers.
- Movement watchdog detects a non-moving candidate and selects a working fallback.
- No-progress condition terminates with a diagnostic instead of looping.
- Date interval newer than current position chooses `newer`.
- Date interval older than current position chooses `older`.
- Date interval overlapping current position enters collection without an unnecessary seek.
- Seek phase does not collect media outside the interval.
- Collection phase preserves overlap and deduplication.
- User-visible scan labels contain `older messages` / `newer messages` and no ambiguous geometry wording.
- Date interval hides/disables manual direction controls.
- Position restoration is never reported as successful when only ratio fallback was used.
- Chromium, Firefox, and userscript builds execute the same navigation state machine.

### Manual/live

- Firefox extension on a long Discord channel, current → older and current → newer.
- Userscript on the same channel and starting positions.
- Date interval months before the current position.
- Date interval months after an old current position.
- Current position already inside the interval.
- First-message boundary on at least two Discord UI languages.
- Latest-message boundary with today-only time presentation and with a localized Yesterday separator.
- Start-position restoration and latest-message movement, with failures displayed honestly.

## Release policy

This work must ship as a 7.2 prerelease first. Automatic boundary movement and date seeking are navigation-critical and must not replace 7.1 stable until Firefox extension and userscript live tests pass the manual matrix above.
